## 一、四视图：不是"画四张图"，是"同一份数据投影四次"

**关键设计**：四张图**没有任何一处各自算尺寸**。它们共用柜体的三维分量
`X∈[0,W]`（宽）`Y∈[0,D]`（进深，背→前）`Z∈[0,H]`（高），每个视图只做
「取两个分量 + 平移/翻转」：

| 视图 | 映射 | 说明 |
|---|---|---|
| 正视图 | `(X,Z) → (fx+X, fy+Z)` | 基准视图 |
| 俯视图 | `(X,Y) → (fx+X, ty0−Y)` | Y 翻转 ⇒ 柜背在上 |
| 侧视图 | `(Y,Z) → (sx0+Y, fy+Z)` | 从右向左看，柜背在左 |
| 内部图 | `(X,Z) → (ix0+X, fy+Z)` | 与正视图同向，门/抽面画成虚线 |

因为映射里**不存在"重新算一遍尺寸"这一步**，「长对正 / 高平齐 / 宽相等」
就不是"两边都写对了"，而是**结构性保证** —— 只要映射成立，它们必然成立。
再加上 6 条投影衔接线（品红点划线）把三条不变量画成看得见的线。

排布按第一角投影法（GB / ISO-E）：俯视在正视**正下方**，侧视在正视**正右方**，
内部图在侧视正右方。多柜时按每柜**实际占用图幅宽度**左右并排，不做估算。

### 「衔接要合理」被写成了 57 条可执行断言

`app/verify/views-acceptance.ts`（`npm run verify:views`）：

- **A** 映射不变量：长对正 / 高平齐 / 宽相等 / 内外同向 / **声明属实**
- **B** 第一角排布 + 6 条衔接线
- **C** 跨视图内容一致性：同一块板在四个视图里的尺寸与位置必须逐一对上
  （顶板 / 底板 / 侧板 / 中立板 / 层板 / 背板 / 门宽链 / 踢脚板 / 内空 / 挂衣杆）
- **D** 图元健康度（图层白名单、无零长度线、无重复图元）
- **E** 假设清单（没工艺依据的地方必须说出来）
- **F** 确定性与平移不变性
- **G** **负样本 6 项**：故意破坏必须被检出
- **H** 多柜并排
- **I** 标注可读性 —— 板件名标签不许互相压住
- **J** 缩放到图幅不许把字裁掉

> **关于负样本**：`G` 组不是装饰。一条**读错了地方**的断言可以长期绿灯。
> 本轮的 A 组一开始就踩了这个坑：不变量读的是视图**自己声明的** `meta.bbox`，
> 于是把图元破坏了、`meta` 没变，6 个负样本里有 5 个照样通过。
> 现在所有判定都从**图元实际坐标**现算，并额外加了一条
> 「声明属实」断言（`meta.bbox` 必须等于实际包围盒）。

## 二、AI 记忆：把「我告诉过你」编译成「机器拦得住」

### 为什么门挂在 CommandBus 上，而不是挂在 AI 上

CommandBus 是唯一写入口，UI 点击、拖动、AI、MCP、脚本**五条路都经过它**。
门装在这里：

- **"你说过的话"既拦得住 AI，也拦得住自己的手滑** —— 你亲口说了"总高不超过 2400"，
  那么鼠标拖过头同样会被拦住，不需要 AI 在线
- **AI 不在线也生效** —— 记忆是本地规则，不是"再问一次模型"
- **记忆是纯数据 + 纯函数编译产物，永不被写进模型文件**，导出、备份、回放都不带它

### 数据结构：Correction → 编译 → Gate

```
Correction（JSONL 一行一条，可进 git）
   ↓ compileCorrections()   纯函数
Gate（可执行闭包）  ← 挂在 CommandBus 提交前的最后一道
   ↓
GateHit[]（结构化：哪条记忆 / 你当时的原话 / 怎么改）
```

三条检查形式（覆盖了现有全部真实教训）：

| kind | 判据 | 例子 |
|---|---|---|
| `noNewIssue` | 本次操作是否**新引入**某类问题 | 「背板必须两个方向都拆」→ `IDENTITY-BACKSPLIT-BAD` |
| `maxValue` / `minValue` | 某个 authored 值是否越过阈值 | 「柜体总高不超过 2400」→ `params.height` |
| `pathForbidden` | 是否写了某个禁止的路径 | 「schemaVersion 永远不许被写」 |

**只拦"本次操作新引入的违规"**：复用 strict 模式的 before/after issue 对比，
历史遗留违规不阻塞新操作 —— 否则模型里本来就有一条 ERROR 时，任何操作都会动不了。

### 假记忆防线（这一轮最重要的产品决策）

一条只有自然语言、没有可执行判据的记忆，**看起来和生效的记忆一模一样，
但它什么都拦不住**。所以：

- 记忆条目必须带 `status: active | pending | retired`
- **检不出来的不许进 active** —— 新增记忆时如果不给判定条件，默认就是 `pending`，
  并在界面上当场告诉你「它现在是待编译，拦不住任何东西」
- 面板上「生效中」的必须写出**它现在具体在查什么**（编译产物），
  待编译的必须写出**为什么没生效**
- 标签页上给待编译的数量挂角标，不让它悄悄堆着

### 双向测试：该拦的拦住，**不该拦的必须放行**

`app/verify/memory-acceptance.ts`（48 项）里每条 active 记忆都要过两关：

1. 给一条**必然违规**的命令 → 必须被拦下，且**模型逐字节未变**、错误信息带回原话
2. 给一条**合法**命令 → 必须放行

只有"拦得住"是危险的（一个恒真的检查看起来完美），配上"不误伤"才算数。
另外还有**哨兵记忆**（触发场景现实中造不出来）：只测不误伤，
并检查它引用的 issue code 在**上游源码里真实存在**，防止指向死 code 变成永久哑弹。

### 界面上的形态

命令行粘贴一段 AI 的 Command JSON → 被记忆拦下时：

> 记忆拦截 [mem_004_max_height_2400]：柜体总高被改到超过 2400mm。
> 你当时的原话：「柜体总高不超过 2400mm（行业默认单柜上限）」
> · 建议：上下分柜（拆成两组），或确认工厂确实能接受超高单柜后再改这条记忆

## 三、管理后台：自己加 API 模型 + 自动拉取

`app/server/server.mjs` —— 零依赖 Node http 服务（只用 `node:http` / `node:fs` / 全局 `fetch`）。
这台机器没有 VPS，服务就是本机的一个进程，装框架是纯负担。

### 两条不能动的底线

1. **只监听 `127.0.0.1`**，绝不 `bind 0.0.0.0`。
   绑 `0.0.0.0` 意味着同一个 WiFi 下任何人都能用你的 API Key 花钱。
2. **API Key 不进浏览器**。key 只存在服务端 `.env`（明文，本地），
   HTTP 响应里永远只回**后四位**。输入框永远是空的，
   保存时留空 = 不修改 —— 前端根本没有原文，也不可能"原样发回"。

### 「自动拉取模型」的诚实规则

内置清单是**静态的，一定会过期**。所以：

- 内置清单只用于离线可用 / 探测失败时的兜底
- 真正的权威来源是服务商的 `GET {baseUrl}/models`
- 响应里必须带 `source`：`live`（服务商实时返回，当前权威）/ `builtin`（内置，可能已过期）
- **拉不到就说拉不到**：界面上退回内置清单时必须写明失败原因，
  绝不把内置清单包装成"服务商实时返回"

### 界面能力

服务商预设 9 家（OpenAI / DeepSeek / Moonshot / 智谱 / 通义 / 硅基流动 / OpenRouter / Ollama 本机 / 自定义
OpenAI 兼容端点）＋ Base URL 可任意填 ＋ 模型可任意填 ＋ 温度；
按钮：保存 / ⟳ 自动拉取模型 / 测试连通性（只消耗 1 token 的 ping）；
另有**记忆同步**：写入服务端 `app/memory/corrections.jsonl`（覆盖前留 `.bak`）/ 从服务端载入。

  且永远不会拿用户的真 key 去发请求

## 五、这一轮抓到的真实缺陷（以及为什么值得记下来）

### 1. AI 通道的记忆拦截没有记录（已修）

**现象**：命令行粘贴 AI 的 Command JSON 被记忆拦下，提示是对的，
但记忆面板的"最近一次拦截"永远是空的。

**根因**：命令行的 JSON 分支**绕过** `run()` 直接调 `bus.execute`，自己写了一遍失败处理，
少调了 `noteHit`。而"AI 下次不要再犯"恰恰最该留下痕迹。

**修法**：把执行后的收尾抽成一个 `afterExec(cmd, r)`，四条路（鼠标 / 命令行字母 /
Command JSON / MCP）全部收敛到它。**失败处理只有一份实现，"某条路少做了一步"
这类缺陷在结构上不再可能。**

> 这条是**浏览器验收 B14 第一次跑就红了**抓出来的，不是靠读代码看出来的。

### 2. 内部图 5 组文字互相压住（已修）

`左侧板` 压在 `抽屉面板 ×3` 的说明上、`底板` 压在 `踢脚板` 上、
`中立板1/2` 压在 `挂衣杆 · 距内底 1800` 上。

**修法**：不再手调坐标，改成**声明位置 + 确定性贪心避让**（`LabelPlacer`）。
标签先声明它"应该"贴在哪块板，撞上了沿竖直方向一档一档让开，但不许让出视图 ——
于是"标签不压字"变成一条**随标签数量增长仍然成立**的性质，而不是一次性的手艺。
避让器如果让不开，会**写进假设清单报出来**，不静默压字。

同时把标签尺寸与位置也变成断言：`I` 组（含负样本）+ 浏览器侧用
**渲染器同款字体的 `measureText`** 独立复核。

### 3. 图幅包围盒只按锚点算，文字被裁掉（已修）

内部图下方那句总览宽 **4094mm**（内部图才 2400mm 宽），右端越出图幅 **847mm**；
首屏自动缩放到图幅时被画布右边缘切掉半截。截图里能直接看到。

**修法**（两处）：

- **图幅 bbox 改按"可见范围"算**（文字按字宽/字高，图形按顶点）。
  这个值唯一的用途就是"缩放到图幅时镜头对多大一块"，必须把文字算进去。
  注意**视图级** `meta.bbox` 仍按锚点算 —— A 组投影不变量建立在"锚点范围"上，
  改动它会把一整套断言的含义悄悄换掉，所以专门分成两个函数。
- 那句总览拆成两行、右对齐，与下面"主卧衣柜 2400 × 2400 × 600 mm"同一基准。

新增 `J` 组断言（含负样本）盯住它。

### 4. 管理后台「操作日志」永远折叠着（已修）

`Section` 的 `defaultOpen` 只作为**初始值**，而日志区挂载时必然是空的
（`defaultOpen={log.length > 0}`）—— 于是保存、拉取、写入全都有回执，
用户却一条也看不见，只能自己去点那个折叠三角。**看不见的日志等于没有日志。**

**修法**：`Section` 的 `defaultOpen` 语义改成"只要现在有东西要看就自动展开"，
但用户手动折叠过之后不再强行展开。

### 5. `views.ts` 的标签避让第一次写就崩了（环境约束）

`constructor(private readonly margin = 18)` 这种**参数属性**写法，
Node 直接跑 `.ts` 时（strip-only 模式）不支持，`npm run verify:views` 当场语法报错。
已改成显式字段赋值，并在注释里写明原因 —— 这个约束以后每次都会踩。

### 6. 验收脚本自身的 4 处错误（"先假定断言自己错"）

| 现象 | 真相 |
|---|---|
| 「图幅上点选不产生选择」失败，读数 `null` | 状态栏**没有选中项时根本不渲染**「已选」读数，`null` 才是正确行为 |
| 记忆总览读不到 | `.sec-toggle` 里第一个子元素是折叠三角 `▸`，`textContent` 把三角粘在标题前面 |
| 修上面那条时又踩一脚 | 顺手把空白也 strip 掉，标题变成 `生效5·待编译2·共7`，正则又不匹配了 |
| 内部图标签"越界" | 我的检查忘了减视图原点，拿图纸坐标去比视图局部坐标 |

> 第三条特别值得记：**去掉什么必须是有理由的**。"顺手清理一下格式"
> 会把待核对的原始格式一起毁掉。
