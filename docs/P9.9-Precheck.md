## 1. 约束一：静默丢字段列为 P9.9 必修验收项

**原则（来自审查补充要求）**：投影层遇到可选业务字段时，不得无声丢弃。若字段属于业务语义（材质 / 尺寸 / 结构 / 制造相关），必须 **显式透传** 或 **显式 reject / unresolved**，禁止 silently drop。

**审查结论：当前投影链是"闭集字段 → 静默丢弃"结构，存在三处确认丢字段点。**

### 1.1 `compileProposal.stripUnit` —— DesignProposal → `cabinet.create` 参数（确认丢）

- `ProposalUnit` 接口（`app/src/ai/proposal.ts:40-58`）声明字段：`kind, nickname, width, count, doorCount, rodHeight, applianceName, openingWidth, openingHeight, openingDepth, topDrawers`。
- `stripUnit`（`app/src/ai/compileProposal.ts:240-253`）只显式拷贝上述闭集。
- **`doorMaterial`**：既不在 `ProposalUnit` 也不在 `stripUnit` → 若 AI 经 proposal 路径输出 `doorMaterial:"glass"`，在编译这步被静默丢弃，永远到不了 `makeUnit` / `cabinet.create`。
  - 对照：旧 `compile.ts` 路径（`compile.ts` 中 `doorIntentOf` / `checkDoorMaterial`，grep 命中 118-130 / 228-242 / 658-683）**支持** `doorMaterial` → proposal 路径是唯一缺口。而 `doorMaterial` 是真实业务字段（几何层 `generate.ts:348` `doorMaterial: dr.material` 会消费它），缺口不可接受。
- **`customHardware`**：全局 `app/src` 中无任何字段声明（grep 零命中）→ 既无透传也无 reject，纯静默丢失。按规则必须显式 reject / unresolved。

### 1.2 `visionResultToNormalized.mapUnit` —— VisionResult → NormalizedDesign（确认丢）

- `mapUnit`（`app/src/ai/vision/visionResultToNormalized.ts:48-64`）只拷贝 `kind, width, count, doorCount, applianceName, openingWidth, openingHeight`。
- **`rodHeight` / `openingDepth`**：未从 `VisionUnit` 读取 → 视觉识别到的挂杆高 / 洞口深被静默丢弃。
- 说明：材质 / 五金视觉不可见，走 `caveats`（visionResultToNormalized.ts:96-114）属合理，不算 drop；但**尺寸类**业务字段必须透传。

### 1.3 `snapshot.unitView` —— 模型 → 发给 AI 的快照（确认丢）

- `AiUnitView`（`app/src/ai/snapshot.ts:191-204`）无 `doorMaterial`、无 `customHardware` 字段；`unitView`（`snapshot.ts:339-361`）也未输出二者。
- **`doorMaterial`**：即便经 legacy `compile.ts` 进了模型，快照投影回 AI 时仍被静默丢弃（AI 无法得知"这扇门是玻璃"）。

### 1.4 P9.9 必修验收方向（新增）

1. **Full populated object projection test**：构造一个所有可选业务字段都有值的输入对象（`doorMaterial, rodHeight, openingDepth, customHardware, topDrawers, appliance 全套…`），依次过各投影层，断言输出必须覆盖所有**业务语义**输入字段——要么显式透传，要么显式进 `unresolved` / `notes`，禁止静默消失。
2. **修复点（闭集字段白名单 + 未知字段显式 reject）**：
   - `ProposalUnit` + `stripUnit`：补 `doorMaterial`（真实字段）；对 `customHardware` 这类未声明业务字段，投影层须检测"字段存在但不支持"并显式 reject（进 `unresolved` / `notes`），不得静默丢弃。
   - `visionResultToNormalized.mapUnit`：透传 `rodHeight`、`openingDepth`。
   - `snapshot` 的 `AiUnitView` + `unitView`：透传 `doorMaterial`（及已声明的业务字段）。
3. 复查清单（与用户要求一致）：`compileProposal.ts`、`stripUnit` 类函数、`visionResultToNormalized.ts`、`snapshot` / context 投影、`candidateScoreContext`。

## 2. 约束二：Explanation 不允许成为新的 Truth Source

**现状（已确认）**：`CandidateLayout.explanations`（`app/src/core/candidateLayout/generate.ts:535-540`）已是**投影**——由 `explain`、`family`、`satisfies` 计数等**已有事实**拼成的人话字符串，不是重新计算。

**P9.9 的 `CandidateExplanation`（只读投影）必须满足**：

- **来源严格限定**：`DesignScoreComponent`、`HardFailure`、`GenerationStats`、`Existing Facts`（spatial / collision / `satisfies` 已是派生事实，非重算）。
- **禁止**：
  - 重算 spatial / 重判 collision / 重解 score；
  - 生成新 rule / 生成新 preference；
  - "解释文本" **反向影响**评分或选择。
- **落实点**：`candidateScoreContext.ts`（对 `score.ts` 的只读投影，P9.4 已定）；UI 只渲染 `score.explanations` / 偏好明细 / `generation` 台账，**不回写**到评分或选择逻辑。
- 与 `docs/P9.9-Architecture-Review.md` 的「satisfies 与 components 两套口径」结论一致：解释层只能消费既有判定 token，不得另立一套判定。

## 3. 约束三：Selection 修复优先级提高（身份风险，已确认）

**现状风险（代码实证）**：

- `candidateSignature`（`app/src/core/candidateLayout/generate.ts:341`）已存在，仅用于去重（`547-552`）与统计（`870` / `877`），**未暴露给 UI**。
- 候选 id 由 `candidateLayoutId(taken)` 生成：**位置性**——每轮从 `taken` 空集起算（`cl_001`…）。
- `AIPanel.tsx:530-545` 持久化 selection **仅存 `selectedCandidateId`**（位置 id），sessionStorage key `p96:selectedCandidate`。
- → 重新生成候选后，旧 `selectedCandidateId` 会**错指**到另一份候选（同 id、不同内容）。

**P9.9 修复要求**：

1. selection 存储结构改为 `{ candidateId, candidateSignature }`。
2. 必须把 `candidateSignature` 暴露到 UI 可取的候选对象上：
   - 在 `PlannerPlan.candidates` 的候选上挂 `signature`（推荐，口径单一）；或
   - UI 侧用同一 `candidateSignature` 函数现算（要求该签名口径对 UI 可用且稳定，禁止两处实现分家）。
3. 恢复时**双重校验**：`id 存在` **AND** `signature 匹配`；任一不满足 → **清除** selection。
4. **禁止** fallback 到同 id 新候选。

## 4. 约束四：增加真实字段覆盖测试（mutation）

```

rodHeight: 1200

到一个 AI 设计请求（DesignProposal / PlannerRequest，以实际入口为准），沿

```

全链路断言：

- `doorMaterial` / `rodHeight`（真实业务字段）→ 必须出现在最终模型 / 下游投影中（**透传**）；

- **任一步丢失即测试失败**。

与约束一共享"闭集字段白名单 + 未知字段显式 reject"的实现；同时锁定回归（已能透传的 `rodHeight` / `openingDepth` 经 proposal 路径不得回退为丢失）。

3. **P2-② 变异锚点同步**：`preflight-bugfixes-acceptance.ts` 的 P2-② mutation `from` 锚点仍是旧错行，改为新正确行 `Auditor(doc).run()`。
4. **`browser-probe.cjs` B6 重量快照陈旧值**：硬编码 `244.8 kg` 是 P0-1 之前的**错误几何**（抽面面板被多扣 `2×gap` → 偏小）留下的陈旧值；P0-1 把面板改回正确尺寸后面板变大、总重升到 **`245.1 kg`**（面积 `22.8 m²` 不变）。已将断言更新为 `245.1 kg`。**这是测试值随几何修正而更新，不是掩盖回归。**
