## 一、分解图：从"我生成的"变成"你能开关的"

之前那张分解图是**无条件画出来的** —— 它一直挂在那里，挡着四视图。现在它是一个开关，
**默认关闭**，四视图调好之后再开。

### 为什么是轴测投影，而不是再加一张正投影

四视图已经完整表达了结构与尺寸。分解图要回答的是**另一个问题**：
"这些板是怎么叠在一起、拆开之后各是哪一块"。这个问题需要第三个方向的可见性 ——
只有轴测投影能在同一张图里同时看到顶面 / 前面 / 侧面。所以用等轴测（30°）：

```
u = (X − Y)·cos30°        +X 轴 → 右下
v = Z − (X + Y)·sin30°    +Y 轴 → 左下
                          +Z 轴 → 正上
```

等价于视点在 `(+X, +Y, +Z)` 卦限，因此**恒能看到** `z=z1` 的顶面、`y=y1` 的前面、
`x=x1` 的右侧面。只画这三面 —— 不需要任何隐藏线算法，也**不可能**画到背面去。

### 与开料清单的一一对应是硬约束，不是力求

- 每一块的**三维位置**来自 `assembly.ts`，而 `assembly.ts` 的位置全部由与生成器
  **同一份 layout 派生量**算出 —— 不存在第二套尺寸计算
- 每一块的**裁切尺寸**逐字取自开料清单
- **件号 = 清单里的板件顺序**，气泡里写的就是这个号
- 图上摆出的件数是 **31 件**（按 `qty` 逐件展开，不是"一类一件"），覆盖 **28 类**板件

### 位移量的性质必须说清

`EXPLODE_TIER_BASE` 分层、`EXPLODE_LANE_STEP` 层内错开决定的爆炸距离是**图面表达**，
与真实装配顺序、拆卸行程**无关**。这句话同时写在图上和面板的假设清单里 ——
否则一定有人拿它当工艺参数去开料。

### 三个入口，一个状态

| 入口 | 形态 |
|---|---|
| 工具栏 | `✦ 分解图` 按钮（激活态高亮） |
| 视图面板 | 「分解图（爆炸图）」分区里的开关按钮 |
| 命令行 | `EXPLODE` 打开 / `EXPLODE OFF` 关闭 |

关闭后**逐像素回到**只有四视图的那一帧（验收里比的是整帧指纹，不是"看起来差不多"）。

## 二、AI 调用：标准 OpenAI 兼容形态 · 对话链路 · 局域网模型

### 加一家服务商 = 填一个 baseUrl

服务端把请求转成 `POST {baseUrl}/chat/completions`（带 `response_format: {type:'json_object'}`）。
任何提供兼容端点的服务商都能直接接上：OpenAI / DeepSeek / Kimi / 智谱 / 通义 / 硅基 /
OpenRouter / Ollama / 自建。**换服务商不改代码、不重启服务** —— 这一条由验收
B17 亲自证明（把 provider 换成 `custom` + 一个本机 mock 端点，当场生效）。

### 三层防线：AI 想越权要连破三关

契约（`shared/aiContract.mjs`）是**纯 JS**，因为三方要同时 import 同一个文件：
本地服务（拦 AI 输出）、前端编译器（把动作编译成 Command）、验收脚本（断言一一对应）。
任何一方各写一份都会漂移。

| 层 | 在哪 | 挡住什么 |
|---|---|---|
| 一 · 词汇表 | 契约 | AI 只能从 **18 个动作**里挑名字 + 参数。它**没有机会输出路径** —— 没有 `set(path, value)` 这种东西 |
| 二 · 校验器 | 契约 | 参数多一个键就整条丢掉；数值必须在闭区间内；枚举必须在册。塞 `panels` / `derived` 会在这一层被识别为"未知参数"拒收 |
| 三 · `isWritablePath` | CommandBus | 动作编译出的 Command 仍要过写权限白名单。这一层**不认识"AI"**，一视同仁拒绝一切写派生字段的尝试 |

18 个动作：

```
cabinet.resize      cabinet.setBodyLift   cabinet.setWidthMode   cabinet.rename
cabinet.move        cabinet.nudge         cabinet.rotate         cabinet.setUnitWidth
cabinet.setUnitParam cabinet.renameUnit   cabinet.addUnit        cabinet.removeUnit
cabinet.setBoardMaterial  cabinet.setBackMaterial  cabinet.create  cabinet.duplicate
cabinet.delete      project.rename
```

契约里的铁律（写在文件最前面）：**几何永不来自 AI**；**规则集对 AI 只读**；
**不新增"删除项目"类动作**；动作名必须能在 `compile.ts` 找到实现且**一一对应**。

### 两段式：干跑 → 提交，「预览 === 提交」是结构性保证

界面上的干跑预览走的是 `bus.preview(cmd)` —— **真实管线跑在一个试探模型上**，
不是"另画一遍示意"。所以预览里那个 `params.bodyLift 80 → 120` 之所以可信，
不是因为"两边都写对了"，而是因为**只有一份实现**。提交时执行的是**同一批 Command 对象**。

### 原子性：一条被拒，整份不执行

用户说的是"把踢脚改成 120，再把它改成 2900 高"。如果"2900 高"被规则拒掉、
而"踢脚 120"照样执行了，用户看到的是"AI 干了一半"，而他会以为两件事都办了。

> **半执行的意图比不执行更危险，因为它是静默的。**

所以：只要有一条动作被拒 → **整份计划一条都不执行**，并且必须给出**具体理由**
（第几条 / 共几条 / 为什么），被拒的那几条逐条列在界面上，不是一句光秃秃的「规划失败」。

### 审计要说和界面**同一件事**

`ai.plan` 的审计结果是**三态**，不是两态：

| result | 含义 |
|---|---|
| `ok` | 全部动作通过，整份会被执行 |
| `partial` | 有动作被拒 → 界面上说的是"整份不予执行"，**账上必须也这么说** |
| `rejected` | 整份不成立（解析失败 / 全部被拒） |

早先只记 `ok` / `rejected`，于是"部分被拒"在账上显示为 `ok`，
和界面上那句"整份计划不予执行"**直接矛盾**。这是验收逼出来的（见第六节·缺陷 3）。

### 对话链路：为什么必须分成两个入口

你现在可以**直接跟 AI 说话**了。但界面上是**两个按钮**，不是一个：

| 入口 | 它做什么 | 会不会动模型 |
|---|---|---|
| `对话（不改模型）` | 问尺寸、问板材、问工艺、问建议 | **不会** |
| `生成编辑计划` | 把要求翻译成动作清单，干跑预览，等你点「应用」 | 会（且要你点两次） |

**为什么不能只做一个输入框、让 AI 自己判断该不该改模型？**

因为"这句话有没有动到我的模型"这件事，**必须由你点下的那个按钮决定，不能由模型的判断决定**。
"背板 9mm 够吗"和"把背板改成 9mm"在字面上只差几个字，而对你的模型一个是零影响、
一个会真的改掉尺寸。把判定权交给模型，等于让一次**风格化改写**有机会变成一次**生产参数变更**。

所以对话通道的系统提示词里写死了一条：

```
· 你**不能直接修改模型**。用户若要改尺寸或结构，请让他点「生成编辑计划」把要求说清楚。
  **不要**说"已经帮你改好了"这类话 —— 你没有这个能力，说了会造成误解。
```

这条由验收 B20 亲自看着：整套对话操作跑完之后，**模型版本号一字节未动**。

### 从"能等"到"知道在等"：17 秒的等待必须有反馈

这台局域网模型单次是 **17~27 秒**。一个什么都不显示的按钮，在这段时间里和卡死**长得完全一样**。
所以两个按钮在忙碌时会自己变成 `AI 正在思考… 8s` / `规划中… 8s`（秒数在走）。

同理，推理模型的 `reasoning_content`（思考过程）**不能丢** —— 它是"为什么等了 18 秒"的
唯一解释。现在它作为可折叠的「思考过程」显示在每条回答上方（默认收起）。

正文为空、或请求出错时，界面上是**告警样式**的色块（不是一行灰字），并且写上**可操作的原因**
（"把 .env 里的 AI_MAX_TOKENS 调大"），不是一句"AI 没有回答"。

每条消息下方显示 `model · token 数 · 耗时`。对话历史存 `sessionStorage`
—— 右侧面板是**按需挂载**的，切到「属性」再切回来组件会卸载重建（这个坑见第六节·缺陷 13）。

### 局域网端点：入站监听与出站连接是**两件事**

你给的端点是 `http://192.168.2.2:3002/v1`，实测是一个 **GPT-Load 网关**：

```
GET  /v1/models            + Bearer 123456  → 200，只有 1 个模型 `tao-ds`（owned_by: gpt-load）
GET  /v1/models            不带鉴权          → 401 invalid_access_key
GET  /                      → GPT-Load 的管理界面 HTML
POST /v1/chat/completions  → 支持 response_format: json_object
```

接内网模型时最容易走错的一步，是把"服务只监听 `127.0.0.1`"和"能不能连内网"混起来：

> **`HOST = 127.0.0.1` 管的是入站（谁可以连我），和出站（我能连谁）毫无关系。**
> 以为"接了内网模型就得 bind `0.0.0.0`"的人，会把**本机全部接口连同 API Key 一起**
> 敞开给整个局域网 —— 而换来的东西（能连内网模型）本来就不需要它。

这句话现在写在 `server.mjs` 的 `HOST` 声明旁边，也写在管理后台的「局域网」预设说明里。

顺带一个**真实的坑**（实测踩到，已修）：

```
环境里有  HTTP_PROXY=http://127.0.0.1:5642
→ 用 curl 打局域网端点：502 upstream connect failed（代理把 192.168.2.2 当外网域名去解析）
→ 服务进程内的 fetch：直连，200
```

`lan-probe.mjs` 因此主动把代理环境变量从出站请求里摘掉；服务端也在启动时
`delete process.env[...]` 一遍。理由不只是"能连上"——**把一个可能不必要的第三方代理
卷进携带 API Key 的请求里，本身就是不该发生的事**。
（另附一条隐患：Node 22 的 `fetch` 不读代理变量；Node 24 起 `NODE_USE_ENV_PROXY=1` 可以打开它 ——
一旦有人打开，链路会以一种极难排查的方式断掉。）

### 推理模型的接口契约：这一轮最值钱的发现

`tao-ds` **不是通用模型，是推理模型**。实测：

| 事实 | 数据 |
|---|---|
| 返回 `reasoning_content`（**不是**回答） | 每次都有 |
| 思考 token 占输出 token 的比例 | **89%**（一次简单问答：252 个输出 token 里 224 个是思考） |
| 单次往返耗时 | `/api/test` 17.3s · `/api/ai/chat` 21.5s · `/api/ai/plan` 18.1s |
| 给 `max_tokens: 20` 时 | **推理把 20 个全吃掉，正文是空字符串**，而 HTTP 仍是 200 |

由此得出三条**必须写进契约**的规则，全部已落到代码里：

1. **`max_tokens` 必须显式下发**，不能留给服务商默认值。
   `shared/aiContract.mjs` 导出 `DEFAULT_MAX_TOKENS = 4096`，`buildChatRequest` 带上它。
   理由：留给默认值时，一个"上限偏小"的网关就能让**正文永远是空字符串**，
   而错误信息只会说"模型返回了空内容" —— 完全指不到真因。
2. **`reasoning_content` 不许丢**。它要在 plan 与 chat 的响应里都带回来，界面折叠显示。
3. **连通性测试的判据是"模型有没有说话"，不是"HTTP 通没通"** —— 见缺陷 9。

## 三、账号体系：订阅模式 / 账号使用额度 / AI 模型调用管理

### 两种运行模式，切换是**单向的**

| 模式 | 含义 |
|---|---|
| `local-open` | 还没有任何账号。所有接口不要求 token，行为与加账号体系之前**完全一致**。目的：不破坏任何既有用法，让"先自用、后商业化"这条路走得通 |
| `accounts` | 存在至少一个账号。**所有** `/api` 接口（除健康检查、鉴权模式查询、登录本身）都要求 token |

**一旦建了第一个账号，就没有"悄悄绕过"的口子** —— 删掉账号库文件也不能回到 `local-open`。
面板上明确写出这一点并给出理由，不让人以为这是个随手可翻的开关。

### 角色 → 能做什么，只读一张表

```js
owner    所有者  rank 40  canManage ✓ canDesign ✓ canView ✓
admin    管理员  rank 30  canManage ✓ canDesign ✓ canView ✓
designer 设计师  rank 20  canManage ✗ canDesign ✓ canView ✓
viewer   只读    rank 10  canManage ✗ canDesign ✗ canView ✓
```

全部判定只读 `ROLES` 这一张表，**不许在别处再写一遍 `if (role === ...)`**。

### 订阅档位 → AI 调用额度

| 档位 | 月 token 总量 | 日调用次数 | 模型白名单 |
|---|---|---|---|
| 免费 | 200,000 | 60 | 不限制 |
| 专业 | 5,000,000 | 1,200 | 不限制 |
| 团队 | 30,000,000 | 6,000 | 不限制 |
| 不限 | ∞ | ∞ | 不限制 |

额度按"自然月 token 总量"计，与商用订阅的常见口径一致。
`models: []` 表示不限制，填了就是白名单 —— **这就是"AI 模型调用管理"的落点**。

界面上：账号管理卡（列出账号 / 角色 / 档位 / 最近登录）、角色与档位下拉、
每个账号的 AI 用量读数。

## 四、账号安全：把"实现了什么"和"还差什么"摆在同一个屏幕上

你的要求是「**得保证账号安全问题**」。一条不能违背的原则是：
**"以后再加"这件事必须写在界面上，不能只留在我脑子里。**

所以账号面板有**两栏**：`已实现`（7 条）与 `尚未实现`（7 条），逐一照实列出。

### 已实现（7 条）

1. **口令哈希 + 独立盐 + 定时安全比较** —— scrypt，每账号 16 字节随机盐，
   比较用 `timingSafeEqual`；**参数写进哈希串本身**（`scrypt$N=16384,r=8,p=1$salt$hash`），
   所以将来提高 N 或换 argon2 时可以**逐账号**升级 —— 见第六节·缺陷 2
2. **会话 token 只存哈希，支持过期与停用即踢下线** —— 落盘只有 SHA-256，
   明文只在登录响应里出现一次；存 `sessionStorage` 不存 `localStorage`
3. **失败登录计数与锁定窗口** —— 15 分钟内 5 次失败锁定 15 分钟
4. **角色与最小权限判定** —— 见上表
5. **AI 调用额度（月 token / 日次数）与模型白名单**
6. **管理操作与 AI 调用全量审计** —— `actor / action / target / ip / 时间`
7. **账号库损坏时拒绝启动，不降级为无账号模式**

另外两条不写在清单里但是底线：

- **登录失败与"用户不存在"回同一句话** —— 防用户名枚举
- **口令强度校验**：弱口令表、纯数字、同字符重复、连续序列、长度上限

### 尚未实现（7 条，上线前必须补）

1. ⚠ 没有 HTTPS —— 上线必须由反向代理终止 TLS，本服务本身不做
2. ⚠ 会话不会轮换（refresh）也不能远程撤销单条，只能整账号踢下线
3. ⚠ 没有二次验证（邮件/短信/TOTP），口令是唯一凭据
4. ⚠ 账号库是本地 JSON 文件，**没有并发写保护**，多进程会互相覆盖
5. ⚠ 没有密码找回流程，忘记口令只能由管理员重置
6. ⚠ 审计日志无防篡改（没有链式哈希或外部归档），且与账号库同机
7. ⚠ 上传/模型文件没有按账号隔离配额

> 第 4 条是**最紧迫**的一条：JSON 文件 + 单进程是够自用的，但"上线"意味着
> 多请求并发，那时它就会开始丢账号。换 SQLite/Postgres 是上线的第一步。

### 浏览器端 396 项里，这一轮新增的六组

### 这一轮验收环境的三处加固

1. **mock OpenAI 兼容端点**（`http.createServer`，只实现 `/chat/completions`）。
   真服务商需要真 key、真网络、且回复不可复现；用假 key 打真服务商只能验"失败路径"，
   而**成功路径才是这条功能的全部价值**。mock 的计划从**请求里带的快照**推出来
   （读 `cabinets[0]` 当前的 `bodyLift`），所以不依赖种子数值，前面用例改过模型也照样对得上。
   **它故意不实现 `/models`** —— B15 那组"拉取失败必须如实说失败"依赖这个 404 保持失败语义。

   **mock 必须能区分两条通道。** 规划请求的 user 消息里带 `【用户这一句要求】` 标记 + 一个
   `json` 快照块；对话请求的 user 消息**就是用户原话**。早先这个 mock 只认规划请求，
   于是对话进来时它照规划去解析 —— 回了句"快照里没有柜体，我不知道该改谁"，而那次其实是在提问。
   **通道没分开，mock 就会给出"看起来有回答、其实答错了题"的东西** —— 而那种假回答
   会让"对话链路通不通"这件事**看起来是通的**。
   对话回答里也带 `reasoning_content`，因为真实模型就是那样。
2. **账号库与审计日志强制落临时目录**。验收里要真的**建一个账号**，而默认路径是
   `app/memory/accounts.json` —— 于是每跑一次验收，仓库里就多出一个所有者账号、
   一份假登录历史。那不只是脏，是**危险**：下次真在自己机器上启动时，服务会以为
   "已经有账号了"，直接把注册窗口关掉，而那个账号的口令是验收脚本随手写的。
3. **清扫兜底挂在收尾上**。清理逻辑原本只挂在 `process.on('exit')` 上 ——
   而验收被杀（被上游超时发 SIGINT、浏览器崩、终端关掉）时**根本走不到 exit hook**，
   垃圾就攒下来了（实测 `%TEMP%` 下攒过 9 个，其中还有几个装着假 key 的 `.env`）。
   现在启动与收尾都会清扫 `furniture-cad-*` 命名空间里**超过 6 小时**的残留 ——
   只碰自己的命名空间、只碰够旧的，既收得掉陈旧垃圾，也不会误伤并发运行的验收。

   另外：`verify/out/diagnostics/` 原本是**无条件创建**的，于是每一次正常通过的验收
   都会在证据目录里留下一个空目录。改成只有崩溃时才建 —— **一个什么都不说明的空目录
   比没有这个目录更容易让人误解。**

## 六、这一轮抓到的真实缺陷（15 个）

Phase 3 前段（分解图 / AI 规划 / 账号）8 个：前四个是**写测试之前**先修的 ——
为了写出有意义的断言，必须先把界面做对；后四个是**验收跑出来的**，其中 3 个在第一次跑红了 22 项时才暴露。

Phase 3 后段（AI 对话 / 局域网端点）7 个：**全部是接上你那台真实模型之后才暴露的**。
其中第 9 条（`/api/test` 假阳性）是这一轮最有价值的一条 —— 它说明
**"测试通过"这件事本身也可以是错的**。

### 1. AI 面板与账号面板没有滚动容器（验收跑出来的）

**现象**：B17 / B18 一片红，所有对面板取文本的断言读到空字符串，我一度以为"面板没渲染"。

**根因**：`.side-right` 是 `display:flex; flex-direction:column` 且**自身 `overflow` 可见**；
可滚动性完全依赖 `.panel-scroll` 的 `flex:1; overflow:auto; min-height:0` —— **三个缺一不可**。
这两个新面板用 `<>…</>` 或裸 `<Section>` 作根，**漏了这一层**。于是内容一长
（干跑预览 + 18 项词汇表）就**溢出到面板外面、永远滚不到**。

**修法**：两个面板（含 AccountPanel 的三个 early return）全部补上 `.panel-scroll`，
并加一条常驻结构断言（B19 里"右侧 9 个面板全部有滚动容器"）让它有个哨兵永久看着。

> 这条值得记的原因：**它是一次"测试读不到东西"，而根因是产品缺陷，不是断言写错。**
> 但那 22 项里只有 3 个是这种情况 —— 所以下面第七节的那条铁律依然是对的。

### 2. 口令哈希不是自描述的（验收跑出来的）

**现象**：`口令是 scrypt 哈希 + 独立盐` 这条断言失败 —— 落盘是**裸 hex**，
`verifyPassword(password, salt, hash)` 的参数是分开传的。

**风险**：将来把 scrypt 的 N 提上去（或换 argon2），**老账号就无法验证** ——
而"所有人同一个早上突然登不进来"正是这类改动最典型的翻车方式。

**修法**：新增 `SCRYPT_PARAMS`、`encodeHash` / `parseHash`，哈希存成
`scrypt$N=16384,r=8,p=1$salt$hash`；`parseHash` **兼容早期的裸 hex + 独立盐形态**；
`securityPolicy().passwordHashing` 文案改成把这个串的真实形状写出来；
断言升级为"自描述串正则 + `N ≥ 2^14` + 盐 32 hex 且与串内一致"。

### 3. 审计与界面各说一套（验收跑出来的）

**现象**：负例计划的审计结果是 `["ok","ok"]`，而界面上说的是"整份计划不予执行"。

**根因**：`plan.ok === true` 只表示"有动作通过了"，**不表示整份计划会被执行**。
审计只记 `ok` / `rejected` 两态，"部分被拒"就落进了 `ok`。

**修法**：`result` 改三态（`ok` / `partial` / `rejected`）。
**审计和界面必须说同一件事** —— 一个只给别人看的账本，如果和现场记录矛盾，
它的价值是负的（会让人以为查过了）。

### 4. 审计表不显示 IP（验收跑出来的）

**现象**：面板自己的说明写着"登录、失败登录、账号变更、AI 调用都会留痕
（`actor / action / target / ip / 时间`）"，而表格只有 `时间 / 动作 / 结果 / 对象`。

**修法**：加「来源」列，`String(e.ip ?? '—').replace(/^::ffff:/, '')`。
**说明与实际不符比不写更糟** —— 人会以为他看过了。

### 5. 部分被拒时，界面只剩一句"规划失败"不给理由（写测试前修的）

`aiClient.requestPlan` 在"有动作被拒"时返回 `ok:false`，但 `error` 是服务端给的
`undefined`（服务端在部分被拒时只回 `rejected`、不回 `error`）。于是界面上只剩
一句光秃秃的「规划失败」，而真正的原因躺在没人渲染的 `rejected` 数组里。

**修法**：显式派生 `rejectedNote`，把"第几条 / 共几条 / 为什么"写进 `error`，
并说明整份不执行的理由。

### 6. 被拒动作列表挂在永远不会渲染的那条路径上（写测试前修的）

原代码把 `rejected` 的 JSX 放在 `{reply ? <Section title="AI 的说明">}` 里，
而有拒绝时走的是 `{err ? <Section title="失败">}` —— **列表永远看不到**。

**修法**：把 JSX 提成 `rejectedBlock` 常量，成功 / 失败两条路径共用。

### 7. 应用后预览区立刻消失（写测试前修的）

`AIPanel` 的 `useEffect([version])` 一律 `setRun(null)`；而提交会 bump 版本号 ——
于是人点完"应用全部"只来得及瞥一眼 toast，**想回头核对"到底改了哪几处"什么都没有**。

**修法**：`PlanRun` 加 `committedVersion`，effect 改成"已提交且版本号正是我提交出来的
那一次就留着"；按钮文案改为 `✓ 已应用 N 条`。

### 8. 管理后台在账号模式下会渲染一份假配置（写测试前修的）

它用裸 `fetch`，401 的响应体 `{ok:false,error:'…'}` 是**非空对象**，
被当成 `Settings` 读进 state —— 面板照常渲染**整套模型表单**，每个字段都是 `undefined`，
而它看起来跟读到了配置一模一样。

**修法**：加 `props.token`，新增 `authed()` 包装器（401/403 → `setDenied`，返回 `null`，
调用方停手），渲染层加权限拦下说明。
**规矩：拦下就是拦下** —— 宁可什么都不显示，也不显示一份假配置。
B18b 整组就是为它写的。

### 9. 连通性测试的假阳性 —— **通过一个什么都没验证的测试，比测试失败更坏**（实测逼出来的）

**现象**：`/api/test` 报「✓ 连通性正常。这一条请求只消耗 1 个 token。」—— 而你那台模型
**一个字都没说出来**。

**根因**：原实现发的是 `{ content: 'ping', max_tokens: 1 }`，**只要 HTTP 200 就报通过**。
在推理模型上，这 1 个 token 会被**思考过程**整条吃掉，正文是空字符串，而 HTTP 仍是 200。
实测：

```
ok: true   latencyMs: 17900   completion_tokens: 1   reasoning_tokens: 1
```

顺带一处**事实错误**：那句"只消耗 1 个 token"也不对 —— 实测 `total_tokens` 是 **6**。

**修法**：把这个接口的语义拆成两件事，并在代码里写明为什么是两件：

| 字段 | 含义 |
|---|---|
| `reachable` | HTTP 通了（地址、网络、鉴权都对） |
| `spoke` | **模型真的回了话**（正文非空） |
| `ok` | **= `spoke`** —— 因为"能用"的标准是后者，不是前者 |

配套改动：问一个**必须回话**的问题（"只回复两个字：正常"）、`max_tokens: 512`、
原样返回 `usage` 与 `reasoningChars`、正文为空时给可操作原因。
修完实测输出 token **1 → 61**、正文 **空 → `正常`**、文案改成"用掉 70 token，其中推理 59"。

> 这个缺陷对用户的价值：**它会在你真以为自己配好了的时候告诉你"能用"。**
> 假阳性比假阴性更难发现，因为它不产生任何需要排查的现象。

### 10. 契约里没有 `max_tokens`（实测逼出来的）

**现象**：推理 token 会吃光输出预算，而那时候报错只会说"模型返回了空内容"，指不到真因。

**修法**：`shared/aiContract.mjs` 导出 `DEFAULT_MAX_TOKENS = 4096`，
`buildChatRequest` 加 `max_tokens: opts.maxTokens ?? DEFAULT_MAX_TOKENS` —— **显式下发，不留给服务商默认值**。
理由写在契约注释里（见第二节末「推理模型的接口契约」）。

### 11. 正文为空时只有一句"模型返回了空内容"，两种情况混在一起（实测逼出来的）

**现象**：`/api/ai/plan` 的两个分支（返回的不是可解析 JSON / 正文本身为空）都落到
`extractJson` 的"模型返回了空内容"上。用户拿到这句话完全无从下手 ——
而真相往往是"**把 AI_MAX_TOKENS 调大就能用**"。

**修法**：单独一条空正文分支，按 `finish_reason === 'length'` 给出
"模型的输出预算用完了却没产出正文（输出 N token，其中推理 M）—— 把 .env 里的
AI_MAX_TOKENS 调大，或换一个非推理模型"；审计加 `result: 'empty'` 与
`note: budget_exhausted / empty_content`。

### 12. `reasoning_content` 被完全丢弃（实测逼出来的）

**现象**：用户等了 18 秒，屏幕上没有任何解释 —— 界面上只有几行代码，而模型的思考过程
（唯一能解释"为什么这么久"的东西）被服务端**丢掉了**。

**修法**：`/api/ai/chat` 与 `/api/ai/plan` 的响应都带 `reasoning` 与 `finishReason`；
前端 `ChatTurn.reasoning` 折叠显示（默认收起）。同时 chat 响应带上服务端实测的 `ms`。

### 13. 对话历史切一次页签就没了（验收 B20 抓出来的）

**现象**：B20 "切走再切回来，对话还在" → **0 条**。

**根因**：右侧面板是**按需挂载**的（`{rightTab === 'ai' ? <AIPanel/> : null}`），
切到「属性」再切回来，组件被卸载后重建，`state` 归零。

**修法**：对话历史落 `sessionStorage`（惰性 `useState<ChatTurn[]>(loadChat)` + 每次变更写回，保留最近 40 条）。
**为什么是 `sessionStorage` 而不是 `localStorage`**：对话是**会话级**的工作记录，不是配置。

### 14. 输入框被放进了一个默认折叠的分区（自查发现的）

**现象**：我第一版把输入框放在 `<Section title="输入" defaultOpen={false}>` 里。
而 `Section` 折叠时**整块不渲染** —— 用户打开「AI」页签，**看不到主入口**。

**修法**：把输入框与两个按钮移进对话区里（不另开分区）。
B20 第一条断言就是为它写的："输入框在打开面板的第一眼就在"。

### 15. markdown 的 `**粗体**` 被直接写进了 JSX 与 toast（系统性缺陷）

**现象**：用户在界面上看到的是**字面的星号**：`**从此刻起所有接口都要求登录**`。
一共 4 处：`AIPanel` 的 rejectedBlock、`AdminPanel` 两处、`AccountPanel` 的 toast、`ViewsPanel:99`。

**为什么它值得单列**：在**源码里**它和 markdown 文档长得**一模一样** ——
任何只比对"文本内容对不对"的断言都不会觉得它有问题（内容确实对，只是多了星号）。
它需要的是**换一个维度**看渲染结果。所以修完之后加了一条常驻断言（B19 的文本卫生断言，
遍历 `.side-right` 下所有叶子节点，`textContent` 不许含 `**`）。

**修法**：全部改成 `<b>` 或直接去掉。

## 七、"断言自己写错" 26 项 —— 这条铁律又一次被印证

| B17 耗时断言失败 | 我把显示从 `${ms}ms` 改成 `${(ms/1000).toFixed(1)}s`（**这台模型是 17~27 秒，"26500ms"要在脑子里除一次才读得懂**），断言还写着 `/ms/`。改成 `/\d+\.\d+s/` |

## 八、诚实清单（还没做的 / 已知边界）

1. **DXF 导出仍未接入 app**（Phase 1 遗留，核心验收链最后一环）。
   四视图与分解图的图元已经全部按图层分好
   （`F-CAB` / `PANEL_*` / `F-DIM` / `F-TEXT` / `F-VIEW` / `F-EXPLODE` / `F-CAB-HIDDEN`），
   接 DXF 时可以直接按图层映射到 ezdxf，不需要重新组织数据。
2. **账号库是本地 JSON，没有并发写保护**（见第四节第 4 条）—— 自用够，上线不够。
3. **AI 对话历史只活在当前标签页**：存在 `sessionStorage`（切页签不丢、刷新不丢），
   但**关掉标签页就没了**，也没有落库；多轮上下文只回传最近 12 条。
4. **额度只统计不拦截**：超限时会拒绝（429）并给出提示，但没有"提前预警 / 按账号出账单"的功能。
5. **`PLANS.models` 全部为空**（不限制模型）—— 白名单机制已经就位，但没有填真实取值，
   因为"哪个档位能用哪些模型"是**定价决策**，得你来定。
6. **分解图的位移量不是工艺参数**（见第一节），装配顺序与拆卸行程都没有建模。
7. **内部图仍不含工艺细节**：背板槽、排钻孔位、五金安装孔都没有。
   图纸目前是"结构示意 + 尺寸"，不是"可直接开料的生产图"。
8. **本轮仍未做**：标注系统 `DLI` / `DIMCAB`、右键菜单、3D 视口、`MI` / `O` / `TR` / `EX`。
9. **你那台局域网模型是推理模型，每问要等 17 秒以上**（见第二节末）。
   界面上已经加了"已等 N 秒"的反馈，所以它不会看起来像卡死 ——
   但**如果你嫌慢，换一个非推理模型是最直接的办法**（延迟差一个数量级）。
   `.env` 里的 `AI_TIMEOUT_MS=180000` / `AI_MAX_TOKENS=4096` 是给推理模型留的余量，
   换成快模型之后可以调小。
10. **`verify:lan` 不进 `verify:all`**，因为它依赖你这台机器和这个地址 ——
    换网络环境它就会红，而那种红不是代码问题。它是**按需运行**的。
11. **AI 对话通道没有单独的动作权限**：它只读快照、不产 Command，
    但快照里含全部柜体尺寸。将来做多人协作时，只读用户的对话通道要不要脱敏，是个待定问题。
