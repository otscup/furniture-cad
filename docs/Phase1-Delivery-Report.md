# Phase 1 交付说明：CommandBus 地基 + 可点鼠标的 2D 工作台

> 对应主方案 §L12 第 1 步与第 6 步（关键路径上仅有的两个"不可跳过"的点）。
> 代码在 `app/`，验收脚本在 `app/verify/`，截图在 `app/verify/out/`。

---

## 一、这一阶段到底交付了什么

**一句话**：一个真的能用的 2D CAD 工作台，以及它下面那套"AI 与鼠标同权同位"的写入地基。

| 层 | 交付内容 | 关键文件 |
|---|---|---|
| 真相源 | 语义参数化模型（JSON）。authored 可写，derived 只读且**永不落入模型** | `src/core/types.ts`、`src/core/docFactory.ts` |
| 唯一写入口 | CommandBus：白名单 + 值域夹紧 + 两段式执行 + 结构性变更逆序撤销 + 增量缓存 | `src/core/commandBus.ts` |
| 命令词汇表 | UI / AI / MCP 共用的构造器集合（AI 能做什么变成可枚举清单） | `src/core/commands.ts` |
| 钩子层 | 拖动/夹点 → 语义命令的映射（唯一允许把像素意图翻译成语义变更的地方） | `src/viewport/gripDrag.ts`、`src/core/snapPlace.ts` |
| 视口 | Canvas 2D 自研渲染器、相机、捕捉、命中测试、图层表 | `src/viewport/*` |
| 工作台 UI | 工具栏 / 对象树 / 图层 / 属性（authored↑ derived↓）/ 问题 / 历史 / 命令行 / 状态栏 / HUD | `src/ui/**` |

### 这一阶段刻意守住的三条架构边界

1. **App 只持有视图状态**（相机、选择、工具、面板开关）。模型 100% 归 CommandBus，React 只订阅一个 `version` 数字。
2. **视口不写模型、不画几何**。它唯一的工作是把指针事件翻译成 Command；屏幕上的变化来自 `bus.preview(cmd)`，即"真实管线跑在试探模型上"。
3. **渲染器只认一个 `Scene{project, geom}`**，遇到未知图元直接忽略——渲染层绝不能让界面白屏。

### `verify/bus-acceptance.ts`（105 项）验证的是不变量，不是"能跑"

- 示例模型派生 + 校验：恒等式断言 **0 ERROR**
- 写路径白名单真的拦得住派生字段与越权 op（`panels` / `geometry` / `issues` / `stats` 全部拒绝）
- 值域夹紧**会回报**，不静默改值
- **【预览 === 提交】**：同一条命令，`preview()` 与 `execute()` 得到逐字节相同的模型
- 12 类路径变更 + 6 类结构性变更：`undo` 后与操作前逐字节一致，`redo` 后与操作后逐字节一致
- 派生字段永不进入模型
- `strict` 模式只拦"本次新引入的 ERROR"
- 160 次随机合法编辑后，恒等式断言始终保持 0 ERROR
- 长链撤销归零、审计日志与 `jumpTo` 状态跳转

### `verify/browser-probe.cjs`（108 项）跑的是**真实界面**

真 Chrome（CDP 驱动）、真指针事件、真键盘、真 DOM 取值。**所有读数都从界面上读回来**——这一轮要证明的恰恰是"界面如实反映模型"，而不是"模型自己说自己是好的"。

## 三、这一轮验收抓到的 6 个真实缺陷（都已修 + 已加防复发断言）

| # | 严重度 | 缺陷 | 修法 | 对应的永久断言 |
|---|---|---|---|---|
| 1 | 高 | **背板超幅面只拆一个方向**：2400 衣柜产生 2327×2442 背板，单方向拆完仍放不下 → `RULE-PANEL-OVER-SHEET` ERROR（80 轮随机编辑中 42 次违规） | 改为 **nW×nH 网格拆块**，两种摆放取向取块数更少者 | 面积守恒 `Σ(块长×宽) = 整板面积` + `IDENTITY-BACKSPLIT-BAD` |
| 2 | 中 | **拖动结束后残留极轴追踪线**：`onPointerUp` 清了 drag/preview/readout，漏了 `snap` → 松手后屏幕上留下一条指向虚空的绿色橡皮筋和一个失效的捕捉标记，直到再次移动鼠标才消失 | `onPointerUp` 一并 `setSnap(null)` | B5 / B7 断言松手后 `.vp-hud-snap` / `.vp-hud-read` / `.vp-preview-badge` **全部不存在** |
| 3 | 中 | **捕捉生效时坐标读数是原始指针点**：HUD 显示 741，实际落到 700 → "所见非所得"，CAD 里最不能容忍的一类问题 | HUD 读数改用捕捉后的点（`snap.p`），旁边捕捉标记负责解释"为什么是这个点" | B12 断言"鼠标落在角点附近时 HUD 给出的是精确角点" |
| 4 | 中 | **命令行提示条压在状态栏与提示气泡上**：`position:absolute; bottom:8px` 定位到视口右下角，三者叠成一团不可读的字 | 改为状态栏上方的正常流内容；命令行打开时不渲染 | 断言提示条与状态栏/视口**矩形不相交**；断言 `.toasts` 的 bottom ≥ 状态栏+提示条高度 |
| 5 | 低 | **捕捉类型中英混用**：画布上的标记写"象限点"，HUD 里直接输出英文枚举 `quad` | HUD 改用 `snapKindLabel()` | B12 断言捕捉提示必须匹配中文词且**不含** `end/mid/center/quad/grid/ortho/polar` |
| 6 | 低 | **同一种"移动"操作在审计日志里有两种格式**：拖动写出 `移动「主卧衣柜」Δ(+0, +864)`，命令构造器写出 `移动 主卧衣柜 Δ(0, 864)`（无书名号、正数无符号） | 统一格式，正数强制带 `+` | B6 断言日志里出现带符号的 `Δ(+0, +\d+)` |

另有 1 处**产品诚实性**补充：`fit_units` 总宽策略尚未实现，但类型与 UI 里已有入口 → 新增 `LAYOUT-MODE-NOT-IMPLEMENTED` INFO 在界面上如实说出来（未实现的东西必须被看见，不能静默）。

> 方法上的记录：初次跑浏览器探针时 11 项失败**全部是探针自身写错**（文本拼接、正则、期望公式），0 项产品缺陷；把断言写诚实之后，才暴露出上面 #2–#6 这 5 个真实缺陷。**"断言不可信"比"断言失败"更危险。**

## 四、怎么自己跑起来看

```bash
cd app
npm install          # 首次
npm run dev          # 打开 http://127.0.0.1:5273/
```

验收：

```bash
npm run verify       # 地基不变量（105 项）
npm run verify:ui    # 起 dev server + 真浏览器验收 + 收掉 server（108 项）
npm run verify:all   # 上面两个一起跑
```

常用快捷键与命令（CAD 手感，与 AutoCAD 保持一致）：

| 键 | 动作 |
|---|---|
| `L` / `C` / `S` | 画墙 / 放柜体 / 选择 |
| `M` | 移动（基点 → 第二点） |
| `Ctrl+Z` / `Ctrl+Y` | 撤销 / 重做 |
| `F3` / `F7` / `F8` / `F9` | 对象捕捉 / 栅格 / 正交 / 栅格捕捉 |
| `Home` | 缩放到图幅 |
| `` ` `` | 命令行（输入 `HELP` 看全部命令） |

**命令行里以 `{` 开头的内容会被当作一条完整的 Command JSON 直接送进 CommandBus** —— 与鼠标拖动没有任何区别。这就是"UI / AI / MCP / 脚本 四条路同权同位"在界面上的可验证形态。

### 关键缺口：DXF 导出还没进 app

这是核心验收链 `JSON → Semantic Model → Panel Model → DXF → 能被真实 CAD 软件正确打开` 的**最后一环**。目前 DXF 引擎只在 Phase 0 的 Python 脚本里跑通（ezdxf 1.4.4，R2007 原生 UTF-8），app 里还没有导出按钮。

下一步应该做的事，按优先级：

1. **把 DXF 导出接进 app**（TS 算几何 → 中立 JSON → Python 序列化，Phase 0 已实测分工干净）——打通验收链
2. **标注系统**（DXF 交付必须带真实 DIMENSION 实体，Phase 0 已验证 63 个可选中可编辑）
3. **右键菜单 + `O`/`TR`/`EX`**（补齐 CAD 手感）
4. **3D 视口**（Three.js，与 2D 同一份模型/命令）

### Phase 0 遗留待验证

V3 DWG 通道、V4 浏览器性能、V5 LLM 结构化输出、V6 真实工厂 DXF 回读。
