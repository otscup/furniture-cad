## 三、计划外发现与修复

1. **★ 候选重复 bug（真缺陷）**：协调块最初 `candidates.push(...deduped, ...returned)` 把 ③ 已产出的单柜候选**又追加一遍**（应替换非追加）→ cl_001..003 出现两次、maxCandidates 总数超——candidate-layout/design-score/ai-planner 三套件假红。修复=`candidates.length=0` 后再 push。教训：改"追加为替换"的语义变更要回头查所有已有消费者。
2. **generation 统计挂载语义**：协调路径没启用/没产出时不挂全 0 假统计（`uniqueCoord.length>0` 才挂）——"单柜兼容（协调路径不启用）"的可观测判据。
3. **L 型接触事实的诚实修正**：attach（面贴合）语义派生的接触是 **butt**（共线边贴合）；`corner`（纯角点接触）经 attach 产不出——验收初版断言 corner 是**判据造假**，改为断言真实事实（成员相互垂直 + 面贴合接触）。corner 派生仍是 P2 对用户手摆设计的事实层能力，未被删除或放宽。
4. **变异补丁器备份覆盖坑**：同一文件多个补丁时，第二个补丁会把 `.p97bak` 覆盖成半变异内容 → restore 留残留（M6 首跑实际残留 MUT6 进了 git diff）。修复=每文件只备份一次；SIGTERM 打断循环会跳过 restore，"anchor not unique (0)" 是残留信号。
5. **验收脚本崩溃 ≠ 断言红**：变异使 multiOf(set) 为空时 `multi[0]!` 连环崩 → 全部改守卫式失败断言，保证 55 项永远跑完出总账。
6. **validateDesign 返回形状**：键是 `findings/counts/cabinets`（无 perCabinet）——按真实 API 断言，不猜字段名。
