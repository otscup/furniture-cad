### 三条新的结构性原则（已写进 MEMORY.md）

1. **AI 计划是原子的**：只要有一条动作被拒，整份不执行。半执行的意图比不执行更危险，因为它**静默**。
2. **审计必须和界面说同一件事**：`ok` / `partial` / `rejected` 三态。一个只给别人看、
   却和现场记录矛盾的账本，价值是负的。
3. **口令哈希必须自描述**：`scrypt$N=…,r=…,p=…$salt$hash`。参数升级必须能**逐账号**做，
   否则"升级那天所有人登不进来"。

### 本轮抓到的真实缺陷（8 个，详见 Phase3 报告）

**写测试前先修的（4 个）**

1. **部分被拒时界面只剩一句「规划失败」不给理由** —— 服务端部分被拒时只回 `rejected` 不回 `error`，
   而 `aiClient` 原样透传 `undefined`。修：显式派生 `rejectedNote`（第几条/共几条/为什么 +
   整份不执行的理由）。
2. **被拒动作列表挂在永远不会渲染的那条路径上** —— JSX 放在 `{reply ? …}` 里，
   而有拒绝时走 `{err ? …}`。修：提成 `rejectedBlock` 常量，两条路径共用。
3. **应用后预览区立刻清屏** —— 提交会 bump 版本号，而面板 `useEffect([version])` 一律 `setRun(null)`。
   修：`PlanRun.committedVersion`，"是我刚提交出来的那一次就留着"。
4. **管理后台在账号模式下渲染一份假配置** —— 裸 `fetch` 把 401 响应体 `{ok:false,error}` 当成
   `Settings` 读进 state，于是照常渲染整套模型表单、每个字段都是 `undefined`，看起来像读到了。
   修：`authed()` 包装器（401/403 → `setDenied` 返回 null，调用方停手）。**拦下就是拦下，宁可什么都不显示。**

**验收跑出来的（4 个）**

5. **【高】AIPanel / AccountPanel 没有滚动容器** —— `.side-right` 是 flex 列容器且自身不可滚动，
   可滚动性全靠 `.panel-scroll` 的 `flex:1; overflow:auto; min-height:0`（三个缺一不可）。
   两个新面板用 `<>` 或裸 `<Section>` 作根漏了这层 → 内容溢出到面板外、永远滚不到。
   加常驻结构断言（"右侧 9 个面板全部有滚动容器"）看着它。
6. **【高】口令哈希不是自描述的**（裸 hex + 独立盐）→ 见上面第 3 条原则。
7. **【中】审计与界面各说一套** —— 负例计划账上记 `ok` 而界面说"整份不予执行"。修：三态。
8. **【中】审计表不显示 IP** —— 面板说明写了会记 `ip`，表格却没有这列。**说明与实际不符比不写更糟。**

# 2026-09-24（续）Phase 3 后段：AI 对话 · 局域网模型 · 真端点实测

**用户这一轮的要求（逐字）**：
> `可以接ai对话，可以接通局域网的ai模型，测试模型：URL：http://192.168.2.2:3002/v1  密码123456`

拆成三件事：① 界面上真正能**聊**；② 能连**局域网**模型（不是只支持公网服务商）；③ 用给定端点**实测**。

## 端点实测（决定了整个设计）

```
GET  /v1/models   + Bearer 123456 → 200，只有 1 个模型 tao-ds（owned_by: gpt-load）
GET  /v1/models   不带鉴权        → 401 invalid_access_key
GET  /               → GPT-Load 管理界面 HTML
```

**这是推理模型，不是通用模型** —— 这一条改变了接口契约：

| 事实 | 数据 |
|---|---|
| 返回 `reasoning_content`（**不是**回答），`content` 可能为空 | 每次 |
| 思考 token 占输出 token | **89%**（简单问答 252 输出里 224 是思考） |
| 单次往返 | `/api/test` 17.3s · `/api/ai/chat` 21.5s · `/api/ai/plan` 18.1s |
| `max_tokens: 20` 时 | 推理吃光 20 个，正文是**空字符串**，HTTP 仍是 200 |

支持 `response_format: json_object`。plan 的 prompt 2753 token，用 2879（含 2560 cached）。

## 四条新的接口契约（已落到代码）

1. **`max_tokens` 必须显式下发** —— `aiContract.mjs` 导出 `DEFAULT_MAX_TOKENS = 4096`。
   留给服务商默认值时，一个"上限偏小"的网关能让正文**永远为空**，而错误只说"模型返回了空内容"。
2. **`reasoning_content` 不许丢** —— plan 与 chat 都带 `reasoning` / `finishReason` 回去，界面折叠显示。
   它是"为什么等了 18 秒"的唯一解释。
3. **连通性判据是"模型有没有说话"，不是"HTTP 通没通"** —— `reachable`（HTTP 通）/ `spoke`（回了话）/ `ok = spoke`。
   **通过一个什么都没验证的测试，比测试失败更坏。**
4. **收到 HTTP 响应本身就说明地址是通的** —— 401 是"鉴权没过"不是"连不上"，
   只有网络层异常（ECONNREFUSED / DNS / 超时）才算不可达。两者的修法完全不同。

## 本段抓到的 7 个真实缺陷

9. **【高】`/api/test` 假阳性** —— 原实现 `{content:'ping', max_tokens:1}`，**只要 HTTP 200 就报"连通性正常"**。
   实测推理模型这 1 个 token 全被思考吃掉、正文空，却报通过（17.9s、completion_tokens=1、reasoning_tokens=1）。
   顺带一处事实错误：那句"只消耗 1 个 token"也不对（实测 total=6）。
   修：拆 `reachable`/`spoke`，`ok = spoke`，问"只回复两个字：正常"、`max_tokens: 512`。
   修后实测输出 token **1 → 61**、正文 **空 → `正常`**。
10. **契约里没有 `max_tokens`**（见契约 1）。
11. **plan 空正文诊断不具体** —— 非 JSON 与空正文两种情况都落到"模型返回了空内容"，
    用户无从下手（真相是"把 AI_MAX_TOKENS 调大就能用"）。修：单独一条空正文分支，
    按 `finish_reason === 'length'` 说明；审计加 `result: 'empty'`。
12. **`reasoning_content` 被完全丢弃**（见契约 2）。
13. **【高】对话历史切一次页签就没了**（B20 抓出来）—— 右侧面板**按需挂载**，
    切到「属性」再切回来组件卸载重建、state 归零。修：落 `sessionStorage`（保留最近 40 条）。
    **选 sessionStorage 不选 localStorage：对话是会话级工作记录，不是配置。**
14. **输入框被放进默认折叠的分区**（自查）—— `Section` 折叠时整块不渲染 → 打开 AI 页签看不到主入口。
    修：移进对话区。
15. **markdown `**粗体**` 被直接写进 JSX / toast**（系统性，4 处）—— 用户看到字面的星号。
    `AIPanel` rejectedBlock / `AdminPanel` 两处 / `AccountPanel` toast / `ViewsPanel:99`。
    **为什么值得单列**：源码里它和 markdown 文档长得一模一样，任何只比对"文本内容对不对"的
    断言都不会觉得有问题 —— 它需要**换一个维度**看渲染结果。修完加常驻断言（B19 文本卫生：
    `.side-right` 所有叶子节点 `textContent` 不许含 `**`）。

## 架构决策

- **AI 面板两个入口**（不是一个大输入框）：`对话（不改模型）` / `生成编辑计划`。
  **"这句话有没有动到我的模型"必须由用户点下的按钮决定，不能由模型的判断决定** ——
  "背板 9mm 够吗"和"把背板改成 9mm"字面差几个字，一个零影响、一个改生产参数。
  对话通道的系统提示词写死"你不能直接修改模型…不要说'已经帮你改好了'"。B20 断言"对话后版本号一字节未动"。
- **17~27 秒的等待必须有反馈** —— 按钮变 `AI 正在思考… 8s`（秒数在走）。否则和卡死长得一样。
- **入站监听 ≠ 出站连接**：`HOST = 127.0.0.1` 管"谁可以连我"，和"我能连谁"无关。
  以为"接内网模型就得 bind 0.0.0.0"的人会把全部接口连同 API Key 敞开给整个局域网，
  而换来的东西本来就不需要它。这句话写在 `server.mjs` 的 `HOST` 旁与后台局域网预设说明里。
- **出站一律摘掉环境代理**：本机有 `HTTP_PROXY=127.0.0.1:5642`，会把 `192.168.2.2` 当外网域名解析
  → curl 拿到假 502。服务端与 `lan-probe.mjs` 都 `delete process.env[...]`。
  另附隐患：Node 22 `fetch` 不读代理变量，Node 24 起 `NODE_USE_ENV_PROXY=1` 可打开 ——
  一旦有人打开，链路会以极难排查的方式断掉。
- **`PROVIDERS.lan`** 预设（`局域网 / 内网（OpenAI 兼容）`），并说明内网模型常见故障与云端**相反**
  （不是 Key 不对，多是 IP 不通或被代理挡）。

## 本轮最重要的发现（三条）

1. **【高】纠错只能"拦"，永远不能"教"** —— 实测全仓搜索：`corrections` 的唯一去处是
   `src/state/memoryStore.ts:39` 的 `bus.setGate(...)`；而 `shared/aiContract.mjs:502` 的
   `buildSystemPrompt()` **不接受任何参数**（全仓唯一调用点 `:599`）。
   → **纠错从未进入模型的提示词。** 而 `CheckSpec` 只有 4 种，全部要求"可判定"；
   §2.4 举的 8 类典型 AI 错误里只有 3 类能编译成 CheckSpec，其余 5 类（指代/量纲/动作选错/
   臆造数字/交互策略）**只能永远停在 pending，且没有任何机制能推它生效**。
   → 修法：**纠错拆三通道** —— Gate（拦，现有）+ **Prompt（教，反例 few-shot 进提示词）** +
   Test（钉，转回归断言）。**prompt 这条是唯一能解决"同一个错犯三次"的通道**，因为模型唯一会读的地方就是提示词。

2. **【高】账号在服务端、记忆在浏览器** —— 账号/会话/额度/审计在 `server/auth.mjs`，
   而纠错记忆在 `correctionStore.ts:16` 的 `localStorage`；服务端 `/api/memory`（`server.mjs:918-937`）
   是**单一全局文件**，`Correction` 里 `userId`/`tenantId` **0 处引用**。
   → 换电脑/换浏览器/清缓存 = 调教半年的记忆全没。**这是商业化的前置阻塞项。**

3. **【中】AI 在"没有数据"的情况下被要求回答尺寸** —— `buildSnapshot()` 只给语义参数，
   不给任何派生量（这是**对的**，防腐蚀）。但后果是：所有"侧板多高/门缝多少"的问题 AI 只能编，
   **而用户问得最多的恰恰是这类**。→ 建议加 `POST /api/explain` 确定性解释通道，
   AI 从"计算者"变"转述者"。**当前最危险的错误类型不是"改错了"，是"答错了而听起来很对"。**

## 勘察到的现状（决定了设计）

- **夹点已经是语义句柄**：`hitTest.ts:14 GripRole` = `cab-width-l/r`、`cab-depth-f`、`cab-move`。
  所以平面图上"线"到"语义"的映射**已经存在**，缺的是**立面图/四视图图幅里**的线。
- **框选已实现且已接线**：`hitTest.ts:139 boxSelect`（窗口/交叉，AutoCAD 约定）+ `Viewport.tsx:373/460`。
  多选 `App.tsx:62 selection: string[]`。**圈选设施已就位，缺的是把它交给 AI 的语义。**
- **AI 契约最小粒度是"柜体"**：`aiContract.mjs:255 TARGET_KEYS` 只有
  `cabinetId/cabinetName/roomId/roomName/unit` —— **没有"部件"这一层**（门缝/层板线/踢脚线都指不到）。
- `compile.ts:116-121` 有一张**"做不到"表**（如实登记了"没有给已有分区加门的动作"）—— 扩展时必须保持这个诚实。
- `buildCabinetViews` **一次全出 4 视图**；`ViewOpts`（`views.ts:124`）只有 `x/y/gapTop/gapSide/gapInt`，

## 两条必须守住的判断（这是本轮的价值）

1. **A 不能做成"把这条线挪 50mm"** —— 模型里**没有线这个对象**（`Project` 只有 rooms/walls/cabinets，
   `Prim` 是派生）。铁律是"拖动 = 改语义参数，严禁改坐标/线条"。
   → 正确做法是新增**几何 → 语义的反查层 `PickLine`**，且**必须由生成器同时产出**
   （不能事后反查 —— 那等于另写一份判定，`validate.ts:9-11` 明确禁止"校验器自己另算一遍"）。
   AI 收到的是 `{cabinetId, part, paramPath}`，**永远收不到坐标**。
2. **B 的中间产物不能是"正面图"，必须是"候选语义方案"**（界面上看起来一样）。
   一句话理由：**600 的进深从哪来？** 正面图里没有深度信息 —— 从正面图反推四视图只能靠猜，
   而那正是现有 `views.ts` 用结构映射消灭掉的问题（长对正/高平齐/宽相等）。
   → 风格 = **一组语义参数**（放规则集，换工厂=换文件），不是图面样式；
   → 变体**不写进 `Project`**（真相源只能有一个），选定后才走现有 `CMD.createCabinet` 落地；
   → 每份候选带自己的 `issues` → **客户选风格时就能看到"门板高 2302 超限"**（纯增量价值）。

## 建议顺序：先 B 后 A

B 风险低得多（`ViewOpts.kinds` 一个可选字段 + `buildVariants()` 纯函数 + 复用现有命令）；
A 要新增一层反查，**必须与几何同源才不漂移**（本项目最容易做错的一类）。
且 B 直接对客户产生价值。A 还要先定 `CabinetPart` 闭合词汇表的边界（太粗指不准、太细模型选不对，
和 18 个动作的取舍是同一个问题）。

"局部改动与整体对接"**已经是结构性保证**（改语义参数 → CommandBus → derive → IDENTITY-* 断言）。
真正缺的是**影响面提示**：点一条层板线说"往下挪 200"，用户不知道会连带改变门板高/抽屉分格/铰链数。
后端已经算得出来（`geom.layout` 前后 diff），只是没展示 → A5。
